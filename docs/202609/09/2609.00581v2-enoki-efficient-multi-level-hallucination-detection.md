## 摘要
确保事实性仍然是高风险场景中部署LLM的关键挑战。现有的幻觉检测器通常仅作用于单一层级：基于声明的方法提供可解释的事实单元，而基于跨度的方法定位不受支持的文本。弥合这些视图的成本高昂，因为重型LLM管道需要多次分解和验证调用，而模块化系统则需要额外的声明到跨度对齐。我们提出Enoki，一种用于多层级幻觉检测的开放信息抽取框架。Enoki提取基于文本锚定的关系事实，对照证据进行验证，并将不受支持的事实映射回幻觉跨度。这种共享表示使得无需单独对齐即可实现声明级验证和跨度级定位。Enoki支持基于LLM、基于编码器和基于规则的抽取机制，通过统一接口平衡准确性和推理成本。实验表明，Enoki在使用更少资源的情况下与强声明级系统保持竞争力，并在细粒度跨度和实体级定位上取得了优越性能。我们还发布了EnokiQA，一个具有对齐的声明级验证和跨度级定位标注的双粒度数据集。

## Abstract
Ensuring factuality remains a critical challenge for deploying LLMs in high-stakes settings. Existing hallucination detectors usually operate at a single level: claim-level methods provide interpretable factual units, while span-level methods localize unsupported text. Bridging these views is costly, as LLM-heavy pipelines require multiple decomposition and verification calls, and modular systems need additional claim-to-span alignment. We propose Enoki, an Open Information Extraction framework for multi-level hallucination detection. Enoki extracts text-anchored relational facts, verifies them against evidence, and projects unsupported facts back to hallucinated spans. This shared representation enables claim-level verification and span-level localization without requiring separate alignment. Enoki supports LLM-based, encoder-based, and rule-based extraction regimes, balancing accuracy and inference cost through a common interface. Experiments show that Enoki remains competitive with strong claim-level systems while using fewer resources and achieves superior performance on fine-grained span- and entity-level localization. We also release EnokiQA, a dual-granularity dataset with aligned claim-level verification and span-level localization annotations.

### 1. 核心问题与整体含义（研究动机与背景）

- **核心问题**：大语言模型（LLM）在知识密集型应用中常生成缺乏证据支持的流畅陈述，即“幻觉”（hallucination）。在高风险与检索增强（RAG）场景中，用户需要的不仅是简单的二值事实性评分，而是能够定位“回答中哪些部分不受支持”的可操作反馈。
- **现有方法的断层**：
  - **声明级（claim-level）检测**（如 FActScore、SAFE、VeriScore 等）：将生成文本分解为事实单元并逐一验证，可解释性强，但可靠性依赖分解质量——若存在省略的参数、修饰语、时间条件等，验证器评估的命题可能与原回答不一致。
  - **跨度级（span-level）检测**（如 RAGTruth、MuSHROOM、PsiloQA 等）：可精确定位引起幻觉的文本片段，但跨度标签本身不暴露被检验的事实结构。
- **桥梁难题**：要统一两种视图，传统管线需要“声明分解 → 验证 → 声明到跨度对齐”等多步串联，代价高昂且容易在分解、验证与定位之间传播错误。
- **本文方案（Enoki）**：提出基于**开放信息抽取（OpenIE）**的多粒度幻觉检测框架。通过提取“文本锚定关系事实”，使**声明级验证**与**跨度级定位**共用同一中间表示，无需单独的声明到跨度对齐模块。

### 2. 方法论：核心思想与关键技术细节

#### 核心思想
- 从回答的每个句子中抽取 OpenIE 风格的关系三元组 (subject, predicate, object)，这些事实**锚定在原文中**；对每个三元组对照参考上下文进行验证；将不受支持的事实中“新引入的信息片段”（delta span）投射回原句，得到幻觉跨度。
- 由于事实与原文文本绑定，同一表示天然支持声明级验证与跨度级定位，不需要额外的对齐步骤。

#### 增量事实构建（Incremental Fact Construction）
- 将相关关系事实组织为逐步细化的自包含组。每一步添加一个小信息片段，使验证器能区分“支持的粗粒度事实”与“不支持的精细化增量”，并把错误定位到新引入的文本跨度上。
- 示例：回答“Enoki is a mushroom cultivated in northern China.”，Enoki 分解为三个嵌套事实：
  1. Enoki | is | mushroom（entailed）
  2. Enoki | cultivated in | China（entailed）
  3. Enoki | cultivated in | northern China（not entailed）→ 将“northern”定位为幻觉增量。

#### 验证机制
- 将每个三元组转换成文本假设（hypothesis），由 NLI 风格验证器打分。
- 长上下文被切分为碎片（fragment），碎片间保留一句重叠；每个事实对所有碎片打分，取最大蕴含分数作为最终结果（chunk-wise max aggregation）。

#### 三种抽取后端（Fact Extraction Backends）
| 后端 | 说明 |
|---|---|
| **OpenIE baselines** | Stanford OpenIE、MinIE、OpenIE6 等经典系统。 |
| **Enoki-LLM** | 基于 CycleOIE 的 LLM 抽取提示，额外加入三条增量分解准则（含示例），鼓励事实自包含且逐步扩充。 |
| **Enoki-Rule** | 基于 spaCy en_core_web_trf 依存关系解析的 35 条确定性规则，通过“智能体辅助迭代式规则开发流程”构建。 |
| **Enoki-Encoder** | 基于 OpenIE6 的迭代式网格标注（IGL）架构，编码器从 BERT-base 换成 ModernBERT-large；将原始的逐行交叉熵损失改为**基于匈牙利匹配的置换不变集合预测损失**（借鉴 DETR），解决增量抽取中黄金三元组行序不稳定问题。 |

### 6. 主要结论与发现

1. **实体级检测中 Enoki 优势最明显**：Enoki-LLM 在 HalluEntity 上取得 AUROC 79.70 / AUPRC 55.09，比最强隐式检测器（GPT-5.2 零样本，AUPRC 36.63）高约 **+15.3 AUPRC**。
2. **跨度级定位中显式验证高度有效**：Enoki-LLM 在 MuSHROOM 与 PsiloQA 上最优（Span Coverage F1 = 52.07 / 71.15），比 OpenIE 基线最高提升约 **+8.0 / +7.1**；RAGTruth 上分布内训练的隐式方法仍最强，但 Enoki 未经过 RAGTruth 训练也保持竞争力。
3. **句子级二分类结果较混同**：Enoki-LLM 在 RAGTruth-250 上 F1 最高（76.42，比 Claimify 高 +9.8），但在 FactCheck-Bench 与 ANAH-250 上不如部分强基线（NLI 直接应用、RefChecker 等）。
4. **规则与编码器后端在效率和效果间取得良好平衡**：Enoki-Rule / Enoki-Encoder 在多数基准上大幅优于标准 OpenIE 基线，且推理速度快约两个数量级。
5. **匈牙利匹配消融有效**：相比原始行级 IGL 损失，置换不变的匹配损失在三个跨度级基准上显著提升。
6. **共指消解作为预处理效果依赖数据集**：对 RAGTruth/ANAH 有正收益，对 HalluEntity/PsiloQA 略有负面或中性影响，故设为可选项而非默认启用。
7. **维护了“分解质量”与“验证器选择”解耦的设计目标**：框架便于在不同精度-效率预算下实例化。

### 7. 优点

- **统一表示，免去额外对齐**：文本锚定的 OpenIE 事实同时驱动声明级验证与跨度级投影，管道简洁。
- **增量分解设计精巧**：将“粗事实受支持、精细增量不受支持”作为定位幻觉的核心机制，可精准识别最小错误片段。
- **模块化、多后端并行**：LLM/规则/编码器三种抽取方式共用同一验证与投影接口，覆盖不同成本预算，实用性高。
- **方法论改动有理论支撑**：将 DETR 的置换不变匹配思想迁移到增量 IGL 训练中，解决了行序歧义问题，有清晰的动机与验证。
- **评估指标设计用心**：提出 Span Coverage F1 解决细粒度预测被粗粒度黄金标注不公平惩罚的问题（在附录中用实例详细论证）。
- **数据集贡献大**：EnokiQA 是目前少有的集“长答案、长上下文、双粒度对齐标注、多生成器模型”于一体的公开基准，且标注流程透明、具有人工质量评估。

### 8. 不足与局限

- **对抽取质量高度依赖**：若分解器省略命题、合并事实或产出过粗参数，验证器无法恢复缺失的信息结构——这是显式验证范式的固有瓶颈。
- **增量投影假设近似嵌套结构**：当同一事实中多处不受支持或错误交互呈非局部特征时，输出跨度可能比人工最小标注更粗。
- **句子级作用域限制**：跨句共指、省略、话语级归因处理不足；可选共指消解模块的效果不稳定，未能一致受益。
- **验证器敏感性**：最终决策受验证器校准影响较大，弱验证器即便面对良好形成的事实也可能失败。
- **计算成本差异明显**：Enoki-LLM 的大部分时间消耗在抽取阶段（FactCheck-Bench 上 10.97s/句），实际延迟受提示编排与执行方式影响，与 FLOPs 估算并不严格一致。
- **资源信息不透明**：论文对 GPU 型号、数量、训练总时长等关键训练资源未作说明，限制了复现时的成本预估。
- **自动标注存在噪声**：EnokiQA 的标注完全由 LLM 管线生成，其跨度级人工一致性仅 0.569（F1），说明数据集本身仍有一定标注噪声；对“以 LLM 标注训练另一 LLM”的分析性任务而言，可能需要更多人工修正。
- **对比公平性仍有隐忧**：隐式检测器中在 RAGTruth 上最强的模型（FT on RAGTruth）天然见过该分布，而 Enoki 变体未在目标分布上微调；论文虽讨论到这点，但未在同一“零样本”条件下系统比较所有方法的公平基线。
